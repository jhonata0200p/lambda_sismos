¿Por que Arquitectura Lambda y Data Lake Medallion?

bolt Speed Layer (Streaming)

Ingesta continua segundo a segundo desde la API de USGS. Procesa micro-lotes en Spark Streaming y actualiza la Serving Layer en milisegundos para soporte de alertas tempranas.

Latencia: Segundos
update Batch Layer (Lotes Diarios)

Extraccion programada a las 7:00 AM mediante Airflow y procesamiento masivo en Spark Batch. Reconcilia los datos historicos y repara posibles huecos por cortes de conexion.

Precision: Matematica Completa
table_chart Serving Layer (PostgreSQL)

Vistas SQL unificadas que combinan en tiempo de consulta la telemetria en vivo con el historico consolidado, resolviendo la deduplicacion sin sobrecostos de lectura.

Consumo: Millones de queries en ms

Data Lake MinIO & Deduplicacion SQL en PostgreSQL

SELECT *, 'BATCH' AS origen_dato FROM gold_resumen_batch WHERE fecha_evento < CURRENT_DATE

UNION ALL

SELECT *, 'STREAMING' AS origen_dato FROM delta_streaming_hoy WHERE fecha_evento = CURRENT_DATE;

Data Lake Medallion en MinIO

Buckets organizados con politicas de acceso S3 segregadas: Bronze (crudo inalterable), Silver (limpio columnar) y Gold (agregado).

Deduplicacion Deterministica

Streaming tiene prioridad absoluta sobre los datos del dia de hoy; Batch consolida los historicos cerrados. Cero duplicados en la Web.
